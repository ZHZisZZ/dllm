01

Scope and provenance

Every leaderboard cell should ultimately carry one of three provenance states. The current interface does not yet expose these labels per cell, so this document records the boundary explicitly.

Repo-reproduced

Run from this repository with a preserved command, model revision, harness revision, and output artifact.

Reported

Copied from an external model card, paper, or contributor submission. It has not necessarily been rerun here.

Unresolved

A displayed value whose complete run manifest or original result artifact is not stored in this branch.

The branch contains evaluation launchers for LLaDA and Dream, but no complete result manifest for every displayed cell. DiffusionGemma, Nemotron Diffusion, and the agentic benchmarks also lack local launch manifests in this branch; those entries should therefore be read as reported or unresolved until their provenance is attached.

02

Execution stack

The reproducible path in this repository is built around dLLM and its fork of lm-evaluation-harness. The pinned submodule commit for this branch is dca091dbee3d6ee1dab268e9f649aa64e8db97d8.

  1. Launch evaluation through Accelerate and a model-specific dLLM pipeline.
  2. Load the model in evaluation mode and tokenize each harness prompt.
  3. Apply the tokenizer chat template when the selected instruct configuration requests it.
  4. Generate with the model sampler and its declared steps, block size, cache, guidance, and length settings.
  5. Trim generated tokens, apply harness stop sequences, and let the task implementation score the resulting answer.

This describes the repository execution path. It does not prove that every number currently shown on the leaderboard was produced through that path.

04

Accuracy and aggregation

The current page extracts the first numeric value stored in each accuracy cell and displays it as the primary score. If a raw cell contains multiple values—for example 36.9% / 70.7%—only the first value is used by the chart and composite. The meaning of every secondary value still needs source-level documentation.

Current composite
Composite = sum of available primary accuracy values ÷ number of available accuracy cells

The mean is unweighted. Missing cells are excluded rather than treated as zero, and coverage is shown alongside the composite. Because models can have different coverage, task variants, and few-shot settings, the composite is a descriptive overview—not a controlled scientific ranking.

05

TPF and token/s

Tokens per forward pass (TPF)

TPF is displayed as the reported number of generated tokens advanced per model forward pass. It describes decoding parallelism, not elapsed speed. This branch does not yet include formal TPF instrumentation or a shared collection script for every displayed model.

Throughput (token/s)

Token/s is a wall-clock throughput measurement. The Throughput Summary shows only values explicitly marked as TPS in the source data. It never converts or infers token/s from TPF. At present, this leaves three reported IFBench measurements: DiffusionGemma-26B-think, DiffusionGemma-26B-no-think, and Nemotron Diffusion-8B.

Target measurement definition
token/s = generated output tokens ÷ synchronized sampling wall time

A publishable throughput run should record accelerator model and count, batch size, prompt and output lengths, dtype, cache mode, decoding settings, warm-up runs, timed repetitions, synchronization method, software revisions, and the reported statistic (preferably median with dispersion). Fast-dLLM examples in this repository time sampler.sample, but they do not yet constitute a full leaderboard protocol because warm-up, repeated trials, and explicit device synchronization are not standardized there.

06

Missing values

An em dash means that a value is not available to the current page. It does not mean zero. The current data structure does not reliably distinguish “not evaluated,” “evaluation failed,” and “evaluated but not reported”; future result manifests should preserve those states separately.

07

Required result manifest

For a new result to be directly reproducible and comparable, its submission should include:

  • model identifier, immutable revision, tokenizer revision, and chat template;
  • benchmark name, dataset revision, split, task implementation, metric key, and few-shot count;
  • complete evaluation command plus decoding, sampling, cache, stopping, and length settings;
  • dLLM, harness, and dependency revisions, together with the raw machine-readable output;
  • hardware, accelerator count, dtype, batch size, and distributed execution configuration;
  • for throughput: warm-up count, timed repetitions, synchronization boundary, token-counting rule, and summary statistic;
  • provenance state and a durable link to the original artifact or external source.
08

Known limitations

  • Per-cell provenance is not yet visible in the leaderboard interface.
  • Task revisions and sampling configurations are not normalized across all model families.
  • Several benchmark and agentic launch manifests are absent from this branch.
  • Secondary metrics stored in multi-value cells are not defined on the page.
  • The composite does not adjust for unequal coverage and should not be used as the sole basis for a model claim.
  • TPS values currently come from one agentic benchmark and are not a hardware-controlled cross-model study.
